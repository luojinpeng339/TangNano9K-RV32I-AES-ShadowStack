# OS-0 Machine Contract

Status: design freeze for the first command-line runtime.

## CPU reset and software image

- Reset PC: `0x00000000`.
- Instruction image: `src/test_program.hex`, loaded by `src/instr_mem.v`.
- Instruction memory is read-only and combinational-read after the cold-start fix.
- Data memory is word-addressed internally, 1024 x 32-bit words.
- Current functional image is bare-metal; there is no privilege mode, CSR subsystem, MMU or interrupt controller yet.

## Address map

The old GPU MMIO range is retired from the OS software contract. The CPU-only OS build will use:

```text
0x0000_0000 - 0x0000_0FFF   data RAM, 4 KiB
0x0000_1000 - 0x0000_10FF   UART
0x0000_1100 - 0x0000_11FF   security counters / status
0x0000_1200 - 0x0000_12FF   GPIO / LEDs / buttons
0x0000_1300 - 0x0000_13FF   timer, reserved for later
```

The current `mem_stage.v` still contains a legacy GPU decode. Before OS software is considered final, the user will replace that decode with the OS MMIO map; the old GPU behavior is not part of this project.

## UART register contract, version 0

Base: `0x0000_1000`.

```text
UART_TXDATA  +0x00  write: transmit low 8 bits
UART_STATUS  +0x04  read : bit0=tx_ready, bit1=rx_valid
UART_RXDATA  +0x08  read : low 8 bits; read clears rx_valid
UART_BAUD    +0x0C  read/write: clocks per bit, default 234
```

Version-0 policy:

- TX is blocking: software waits until `tx_ready=1`.
- RX is one-byte buffered: a newly received byte sets `rx_valid`; while full, later bytes are dropped and an overrun bit may be added later.
- UART format: 8 data bits, no parity, 1 stop bit, 27 MHz clock, 115200 baud approximation (`234` clocks/bit).
- No interrupts yet; the command monitor polls `UART_STATUS`.

## Security status contract

Base: `0x0000_1100`.

```text
SEC_HALT       +0x00  read: bit0=security_halted
MCYCLE         +0x04  read: 32-bit
MINSTRET       +0x08  read: 32-bit
AES_RETIRED    +0x0C  read: 32-bit
SHADOW_OPS     +0x10  read: 32-bit
CFI_CHECKS     +0x14  read: 32-bit
CFI_VIOLATIONS +0x18  read: 32-bit
SHADOW_DEPTH   +0x1C  read: current protected depth
```

The counters are exposed as read-only OS-0 MMIO registers. A CPU `lw` from the
corresponding address returns the live counter value; ordinary `sw` does not
modify counter state.

The software monitor's stable `status` report is:

```text
H=0
MC=xxxxxxxx
MI=xxxxxxxx
AR=xxxxxxxx
SO=xxxxxxxx
CC=xxxxxxxx
CV=xxxxxxxx
SD=xxxxxxxx
```

Numeric fields are eight uppercase hexadecimal digits and are generated by
RV32I software using ordinary `lw` accesses to the `0x1100` region. This is
not the legacy fixed-window UART reporter.

## GPIO contract

Base: `0x0000_1200`.

```text
GPIO_OUT       +0x00  write: bit0=green, bit1=blue, bit2=red
GPIO_IN        +0x04  read : buttons / external inputs
GPIO_STATUS    +0x08  read : reserved
```

Initial board meaning:

```text
GREEN = CPU not halted
BLUE  = AES activity observed
RED   = security halt or CFI violation
```

Each external LED must use a series resistor. Start with 680 ohms and verify the board's IO voltage/current limits.

## First software commands

The first monitor will support only polling commands:

```text
help
status
ls
cat <name>
aes
cfi
attack
```

`ls` and `cat` initially read a volatile RAM-backed table. Persistent Flash storage is explicitly later work.

## Acceptance gates

OS-0 is not complete until:

1. UART RX receives bytes reliably at 115200 baud in simulation.
2. A CPU load/store can write/read `UART_TXDATA` through MMIO.
3. `status` reads `security_halted` and all seven numeric status fields through MMIO and emits the stable report format.
4. GPIO writes can drive three board indicators.
5. A polling command loop works without interrupts.
